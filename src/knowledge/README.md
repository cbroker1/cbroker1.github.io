# `src/knowledge/`

Hand-written, explicitly approved public knowledge for the site assistant.

## What lives here

`curated-profile.md` — the only file the assistant reads from this directory.
It supplements the site's real content; it does not replace it.

## The corpus boundary

The assistant's corpus is assembled at build time from exactly four sources,
listed in `src/lib/assistant/corpus.ts`:

1. `src/content/projects/**` — published project pages
2. `src/content/writing/**` — published articles (drafts excluded)
3. `src/content/about.md` and `src/content/experience.md`
4. `src/knowledge/curated-profile.md` — this directory
5. the site's own public contact links (`src/lib/site-links.ts`)

Nothing else is read. There is no crawler, no GitHub API call, no LinkedIn
scrape, and no network access at build or at runtime other than downloading the
open-weights model from the Hugging Face CDN. To add knowledge, either publish
a page or edit `curated-profile.md`.

## Updating

```bash
npm run dev            # edit curated-profile.md, refresh the page
npm run build          # regenerates /assistant/corpus.json
npm run assistant:eval # sanity-check retrieval against recruiter questions
```

The corpus is generated by `src/pages/assistant/corpus.json.ts`, an ordinary
Astro static endpoint. It is emitted to `dist/assistant/corpus.json` — there is
no separate build step and no generated file checked into git.

## Attaching a source link to a section

A curated section can point at a real public URL. Put the directive on its own
line directly under the heading:

```markdown
## Where To Find Carl's Code
<!-- source: https://github.com/cbroker1 | View GitHub profile -->

Carl's public projects live on GitHub...
```

The assistant renders that link under any answer built from the section.
Sections without a directive still contribute knowledge but render no link, so
the assistant never cites a page that does not exist. The label is what the
visitor sees; keep it short and verb-first ("View GitHub profile").
